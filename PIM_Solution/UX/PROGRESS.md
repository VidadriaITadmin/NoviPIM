## Zavrnjeni IIS posnetek — vzrok in dokaz

**Zavrnjeni posnetek:** `C:/Users/david/AppData/Local/hermes/images/clip_20260804_210516_3.png` (dejanski IIS izris).
**Referenca:** `../PIM_test/UX_pictures/Nadzorna_plosca.png` (odobreni standard).

**Vzrok (koren):** commitana `App.razor` je imela trdo zapisano `<base href="/" />`. Pod IIS virtualno aplikacijo `/PIM` so relativne povezave na sredstva (`app.css`, `PIM.Intranet.styles.css`, `_framework/*`) izračunale na `/app.css` itd. namesto `/PIM/app.css`. IIS je te zahteve rešil s SPA-nadomestnim HTML-jem (ne CSS), brskalnik pa je CSS tiho zavrgel. Rezultat na posnetku: privzete modre podčrtane povezave, Unicode nadomestne ikone in nestilizirane kartice.

**Popravek:** `<base href="@NavigationManager.BaseUri" />` (App.razor) + `app.UsePathBase("/PIM")` (Program.cs) dasta pravilen base pri korenu in pri `/PIM`. Dodatno: vseh 11 preostalih korensko-absolutnih notranjih povezav pretvorjenih v base-relativne, da sledijo baseu tudi pod `/PIM`.

**Dokaz (lokalni Kestrel, `ASPNETCORE_ENVIRONMENT=Production`, `--urls http://127.0.0.1:5199`):**

| Zahteva | HTTP | Content-Type |
|---|---|---|
| `/app.css` | 200 | `text/css` |
| `/PIM.Intranet.styles.css` | 200 | `text/css` |
| `/bootstrap/bootstrap.min.css` | 200 | `text/css` |
| `/favicon.svg` | 200 | `image/svg+xml` |
| `/PIM/app.css` | 200 | `text/css` |
| `/PIM/PIM.Intranet.styles.css` | 200 | `text/css` |
| `/PIM/bootstrap/bootstrap.min.css` | 200 | `text/css` |
| `/PIM/favicon.svg` | 200 | `image/svg+xml` |

Izrisani `<head>`: `GET /prijava` → `<base href="http://127.0.0.1:5199/" />`; `GET /PIM/prijava` → `<base href="http://127.0.0.1:5199/PIM/" />`. Iste relativne `<link>` povezave se torej razrešijo na `/…` oz. `/PIM/…` in vrnejo CSS, ne HTML. Scoped paket vsebuje pričakovane izolacijske selektorje (`metric-card[b-…]`, `dashboard-panel[b-…]`, `navigation-link[b-…]`, `app-sidebar[b-…]`, `login-card[b-…]`), zato bo nadzorna plošča pod `/PIM` dejansko stilizirana.

**Opomba:** `/_framework/blazor.web.js` vrne 302 na prijavo samo za neprijavljene zahteve (posledica `FallbackPolicy`); prijavni obrazec je navaden POST in ne potrebuje JS, prijavljeni uporabnik pa dobi 200. To ni povezano z dostavo CSS in ni regresija tega sklopa.
