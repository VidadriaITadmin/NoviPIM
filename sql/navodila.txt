# Navodila za izvedbo — 195_RunValidationForProduct.sql

**Kaj naredi:** Ustvari novo, samostojno proceduro `val.RunValidationForProduct(@ProductId bigint)` za hitro validacijo enega izdelka (~150ms namesto ~25s pri obstoječi `val.RunValidation`). Ne spreminja in ne briše ničesar obstoječega.

**Predpogoj:** Standardni zagon migracijskega orodja (`PIM.Migrator`) prek celotne mape `sql\migrations` trenutno odpove, ker `001_CreateSchemas.sql` ne ustreza zabeleženemu checksumu (znan, neškodljiv artefakt iz zgodovine git repozitorija — ne datoteka sama ni pokvarjena). Zato je treba to migracijo zagnati izolirano, iz mape, ki vsebuje samo to eno datoteko.

**Koraki:**

1. Ustvarite prazno začasno mapo in vanjo skopirajte samo to datoteko:
```bash
mkdir "%TEMP%\pim_migration_195"
copy "sql\migrations\195_RunValidationForProduct.sql" "%TEMP%\pim_migration_195\"
```

2. Iz korena rešitve (mapa, kjer je `PIM_Solution`) poženite migrator samo nad to mapo:
```bash
dotnet run --project src\PIM.Migrator -- --migrations "%TEMP%\pim_migration_195"
```

3. Preverite izpis v konzoli — mora javiti uspeh, brez napak (npr. "SUCCESS" ali podoben zaključek brez rdečega besedila).

4. Počistite začasno mapo:
```bash
rmdir /s /q "%TEMP%\pim_migration_195"
```

5. Potrdite v bazi, da je migracija zabeležena:
```sql
SELECT * FROM dbo.SchemaMigration WHERE MigrationFile LIKE '195_%';
```

**Preverjanje, da procedura deluje:**
```sql
EXEC val.RunValidationForProduct @ProductId = <poljuben obstoječ ProductId>;
```
Naj se izvede skoraj takoj (pod pol sekunde).

**Opomba:** Če je bila ta procedura kdaj prej ustvarjena ročno prek SSMS na isti bazi (npr. med testiranjem), to ni ovira — `CREATE OR ALTER PROCEDURE` samo potrdi/osveži isto definicijo, migracija pa jo formalno zabeleži v zgodovino, kar zagotovi, da jo dobijo tudi drugi razvijalci ob naslednjem `git pull` + zagonu migratorja.
